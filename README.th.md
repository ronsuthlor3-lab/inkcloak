# Inkcloak (เครื่องมือทดลอง)

**English: [README.md](README.md)** · **แอป: https://ronsuthlor3-lab.github.io/inkcloak/** · **หน้าผลการวัด: https://ronsuthlor3-lab.github.io/inkcloak/measure.html**

> [!WARNING]
> **นี่คือเครื่องมือทดลองระดับงานวิจัย ยังไม่ได้รับการพิสูจน์**
>
> - Inkcloak **ไม่ได้** ป้องกันหรือบล็อกการนำภาพไปฝึก AI หรือการเลียนแบบสไตล์ มันแค่ใส่สัญญาณรบกวนจาง ๆ ที่ทำให้ **โมเดลขนาดเล็กหนึ่งตัว (MobileNetV2)** มองภาพผิดไป
> - ผลอาจหายไปเมื่อภาพถูกย่อ บีบอัด JPEG ลดสัญญาณรบกวน/ขยายภาพ หรือเพียงแค่เจอโมเดลตัวอื่นหรือรุ่นใหม่ ในการทดสอบของเราเอง (ด้านล่าง) กับโมเดลตัวที่สองที่ผ้าคลุมไม่เคยเห็น ภาพเปลี่ยนไป **มากกว่าสัญญาณรบกวนแบบสุ่มที่แรงเท่ากันเพียงเล็กน้อย**
> - **ใช้แทน [Glaze](https://glaze.cs.uchicago.edu/) หรือ [Nightshade](https://nightshade.cs.uchicago.edu/)** จากมหาวิทยาลัยชิคาโก **ไม่ได้** ถ้าต้องการการป้องกันที่ดีที่สุดที่ศิลปินมีตอนนี้ ให้ใช้เครื่องมือเหล่านั้น
> - ให้มองว่าเป็นเครื่องมือสำหรับเรียนรู้/ทดลอง ไม่ใช่การป้องกันที่พึ่งพาได้

## ทำงานอย่างไร

ทุกอย่างทำงานในเบราว์เซอร์ ไม่มีการอัปโหลด ไม่มีเซิร์ฟเวอร์:

1. ย่อภาพให้ด้านยาวไม่เกิน 512 px เพื่อใช้คำนวณ
2. ใช้โมเดล **MobileNetV2** (TensorFlow.js) แปลงภาพเป็นเวกเตอร์ "ความหมาย" (embedding)
3. ใช้ **Projected Gradient Descent (PGD)** ปรับพิกเซลทีละนิดให้ embedding เคลื่อนเข้าหา **ภาพล่อ** (ลายโมเสกเรขาคณิตสีจัด) โดยไม่เกิน **งบ L∞** ที่คุณเลือก (2–16 ระดับสีจาก 255)
   - งบปรับตามพื้นผิว: บริเวณสีเรียบได้งบเพียง 35% บริเวณที่มีรายละเอียดได้เต็ม เพราะสัญญาณรบกวนจะเห็นชัดที่สุดบนพื้นเรียบ
   - ทุกรอบเฉลี่ยจาก 3 มุมมอง (ภาพเดิม, ย่อ 50%, เติมสัญญาณรบกวนเล็กน้อย) เพื่อให้ไม่หายง่าย ๆ เวลาโดนย่อภาพ
4. ขยายผ้าคลุมกลับเป็นขนาดเต็ม ตัดให้อยู่ในงบ แล้วบันทึกเป็น PNG

ในแอปมีแถบเลื่อนเทียบก่อน/หลัง โหมดขยายความต่าง ×10 และค่า **PSNR / SSIM / เปลี่ยนสูงสุด** ถ้าเลื่อนความแรงหลังคำนวณเสร็จ ตัวเลขจะอัปเดตทันทีแบบ "พรีวิว" (ย่อ/ขยายผ้าคลุมเดิม) ต้องกดใส่ผ้าคลุมอีกครั้งเพื่อคำนวณจริงที่ความแรงใหม่

ข้อจำกัด: ภาพใหญ่กว่า 3000 px จะถูกย่อก่อน ถ้ามี WebGL จะใช้ GPU (ประมาณ 0.15–0.3 วินาทีต่อรอบบนคอมที่มีการ์ดจอ) บนมือถือหรือ CPU จะช้ากว่ามาก

## ผลการวัดจริง (เราวัดเอง 22 ต.ค. 2026)

วัดด้วย [หน้าผลการวัด](https://ronsuthlor3-lab.github.io/inkcloak/measure.html) กับภาพที่วาดด้วยโค้ด 4 ภาพ ขนาด 512×512 (ทิวทัศน์ ภาพคน ลายเส้น ฝีแปรง) 40 รอบ บน WebGL (RTX 4060 Ti, Chromium 152) ข้อมูลดิบ: [`docs/measurements-2026-10-22.json`](docs/measurements-2026-10-22.json) คุณกดวัดซ้ำเองได้ ตัวเลขจะต่างกันเล็กน้อยในแต่ละครั้ง/เครื่อง

- **ระยะที่เลื่อน** = 1 − cosine(embedding ต้นฉบับ, embedding ภาพคลุม) ถ้าเป็น 0 แปลว่าโมเดลมองไม่เห็นความต่าง
- **สุ่ม** = ค่าเดียวกันของสัญญาณรบกวนสุ่ม ±งบ (ใช้งบมากกว่าผ้าคลุม PSNR จึงต่ำกว่า)
- **เข้าใกล้ภาพล่อ** = cosine กับภาพล่อที่เพิ่มขึ้น
- **JPEG q85 / ย่อ 50%** = ทั้งต้นฉบับและภาพคลุมผ่านการแปลงนั้นก่อนวัด
- **MobileNetV2** = โมเดลที่ใช้คำนวณผ้าคลุม · **MobileNetV1 0.5** = โมเดลอีกตัวที่ไม่เคยใช้ตอนคำนวณ (แทน "โมเดลอื่น")

### แปลผลตรง ๆ

- **กับโมเดลที่ใช้คำนวณ ผ้าคลุมได้ผลและส่วนใหญ่ยังอยู่หลัง JPEG q85 และย่อภาพ 50%** — แต่นี่เป็นกรณีง่ายที่สุด เพราะเรารู้จักโมเดลนั้นทุกอย่าง
- **กับโมเดลที่ไม่เคยเห็น ผลน้อยมาก** บน MobileNetV1 (PNG ไม่บีบอัด) ระยะที่เลื่อนเป็นเพียงประมาณ 1.4–1.55 เท่าของสัญญาณสุ่ม และเข้าใกล้ภาพล่อแค่ +0.01 ถึง +0.04 (ภาพลายเส้นที่ความแรงต่ำยังติดลบเล็กน้อย) ระบบฝึก AI จริงใช้ตัวเข้ารหัสภาพอื่นที่ใหญ่กว่ามาก (เช่น CLIP, VAE ของ Stable Diffusion) ซึ่งเรา **ไม่ได้ทดสอบ** และไม่มีหลักฐานว่าผ้าคลุมนี้มีผลกับพวกมัน
- ที่ 4/255 แทบมองไม่เห็น (PSNR ≈ 43 dB) ที่ 16/255 จะเริ่มเห็นบนพื้นสีเรียบและไล่เฉดสี
- ทดสอบแค่ 4 ภาพสังเคราะห์ ไม่ใช่ผลงานศิลปินจริง และไม่ได้ทดลองฝึกโมเดลเลียนแบบสไตล์จริง
- ยังไม่ได้ทดสอบ: ตัวลด noise/ขยายภาพ, การล้างสัญญาณแบบ diffusion, การแคปหน้าจอ, ครอป, ปรับสี — ทั้งหมดนี้อาจลบผ้าคลุมได้

## ใช้คู่กับ Inkseal

ถ้าจะประทับตราด้วย [Inkseal](https://ronsuthlor3-lab.github.io/inkseal/) ให้ **ใส่ผ้าคลุมก่อน แล้วค่อยประทับตรา** ไฟล์ PNG ที่ได้ ถ้าทำกลับกัน ผ้าคลุมจะไปรบกวน (และอาจทำลาย) ลายน้ำที่มองไม่เห็นของ Inkseal

## ทำไมไม่ใช้โมเดลที่แรงกว่านี้

ผ้าคลุมจริงต้องคำนวณ gradient ผ่านโมเดลภาพ ONNX Runtime Web และ Transformers.js ทำมาเพื่อรันโมเดลอย่างเดียว ไม่ให้ gradient ของภาพอินพุตในเบราว์เซอร์ เราจึงใช้ **TensorFlow.js** ที่หาอนุพันธ์อัตโนมัติได้ และเลือก MobileNet ขนาดเล็ก 2 ตัวเพราะไฟล์รวมแค่ ~12 MB และรันได้บนเครื่องทั่วไป การรันโมเดลระดับ CLIP พร้อม gradient ในเบราว์เซอร์ทำได้ในทางทฤษฎีแต่หนักมาก และต่อให้ทำได้ ผลระดับ Glaze ก็ต้องอาศัยงานวิจัยและการทดสอบกับผู้ใช้จริงอีกมาก

## สำหรับนักพัฒนา

ไม่ต้อง build เปิดโฟลเดอร์นี้ด้วย static server ใดก็ได้แล้วเข้า `index.html`

```bash
node --test test/core.test.js
```

เทสต์ครอบคลุมคณิตศาสตร์ใน `js/core.js`: PSNR, SSIM, cosine, แผนที่งบตามพื้นผิว, การ project แบบ L∞, การย่อ/ขยายภาพ และการประกอบภาพสุดท้าย CI รันบน Node 20 และ 22
